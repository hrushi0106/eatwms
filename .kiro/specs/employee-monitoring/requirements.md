# Employee Attendance, Timesheet & Work Monitoring System
# Requirements Specification — V1

---

## 1. Introduction

This document specifies the functional and non-functional requirements for the Employee Attendance, Timesheet and Work Monitoring System (EATWMS). The system serves office, WFH and hybrid employees across four roles: Admin, Manager, Team Lead and Employee.

---

## 2. Roles & Actors

| Role | Description |
|---|---|
| ADMIN | Full system access |
| MANAGER | Access to assigned teams |
| TEAM_LEAD | Access to assigned team members (restricted) |
| EMPLOYEE | Access to own personal data only |

---

## 3. Functional Requirements

### 3.1 Authentication — MUST HAVE V1

- REQ-AUTH-001: The system shall allow users to log in using email and password.
- REQ-AUTH-002: Passwords shall be hashed using bcrypt (min cost 12).
- REQ-AUTH-003: The system shall issue JWT access tokens and refresh tokens on successful login.
- REQ-AUTH-004: Access tokens shall expire after 8 hours. Refresh tokens after 7 days.
- REQ-AUTH-005: The system shall maintain a logout endpoint that invalidates the refresh token.
- REQ-AUTH-006: The system shall record every login and logout in the audit log.
- REQ-AUTH-007: The system shall implement rate limiting on the login endpoint (max 10 attempts per 15 minutes per IP).
- REQ-AUTH-008: The system shall never expose password hashes in API responses.
- REQ-AUTH-009: The system shall support forgot password and reset password flows via email token.

### 3.2 Role-Based Access Control (RBAC) — MUST HAVE V1

- REQ-RBAC-001: The system shall enforce role-based permissions on every protected API endpoint.
- REQ-RBAC-002: Four roles shall exist: ADMIN, MANAGER, TEAM_LEAD, EMPLOYEE.
- REQ-RBAC-003: Employees shall only access their own attendance, timesheets and tasks.
- REQ-RBAC-004: Team Leads shall access data for their directly assigned team members only.
- REQ-RBAC-005: Managers shall access data for all employees in their assigned teams.
- REQ-RBAC-006: Admins shall access all data globally.
- REQ-RBAC-007: Role escalation attacks shall be prevented; users cannot elevate their own role.
- REQ-RBAC-008: The system shall deny access and return HTTP 403 for unauthorized requests.

### 3.3 Employee & Department Management — MUST HAVE V1

- REQ-EMP-001: Admins shall be able to create, update, deactivate and view all employees.
- REQ-EMP-002: Each employee shall have a unique employee code, email, role, department.
- REQ-EMP-003: Each employee may have an assigned manager and team lead.
- REQ-EMP-004: Departments shall be manageable by Admins (create, edit, deactivate).
- REQ-EMP-005: Employees shall be able to view and update their own profile (non-sensitive fields only).
- REQ-EMP-006: Deactivated employees shall not be able to log in.
- REQ-EMP-007: The system shall support employee onboarding with initial leave balance allocation.

### 3.4 Work Modes — MUST HAVE V1

- REQ-WM-001: Three work modes shall be supported: OFFICE, WFH, HYBRID.
- REQ-WM-002: Each attendance record shall be associated with a work mode.
- REQ-WM-003: Employees shall select work mode when initiating check-in.
- REQ-WM-004: Admins may configure work modes (name, description, status).

### 3.5 Webcam Selfie Attendance — MUST HAVE V1

- REQ-WCA-001: Employees shall be required to capture a webcam selfie to check in.
- REQ-WCA-002: Employees shall be required to capture a webcam selfie to check out.
- REQ-WCA-003: The webcam shall only be activated when the employee explicitly initiates check-in or check-out.
- REQ-WCA-004: The system shall display a clear privacy notice before activating the webcam.
- REQ-WCA-005: The employee shall be able to preview, retake or confirm the captured selfie before submission.
- REQ-WCA-006: Selfies shall be uploaded to the server as JPEG/PNG/WEBP, max 5 MB.
- REQ-WCA-007: The server shall generate a SHA-256 hash of each uploaded selfie.
- REQ-WCA-008: Selfie files shall be stored in a secure, non-public directory (local dev) or S3-compatible storage (prod).
- REQ-WCA-009: Selfie images shall only be accessible through authenticated, authorized API endpoints.
- REQ-WCA-010: Employees shall not be able to access another employee's selfie images.
- REQ-WCA-011: The system shall NOT implement face recognition or AI verification in V1.
- REQ-WCA-012: The verification_method field shall be stored as SELFIE in V1, for future extension.

### 3.6 Attendance — MUST HAVE V1

- REQ-ATT-001: The system shall create an attendance record on successful check-in.
- REQ-ATT-002: Only one active (unclosed) attendance record shall be allowed per employee per day.
- REQ-ATT-003: Check-in and check-out timestamps shall be generated by the server, not the client.
- REQ-ATT-004: Employees shall not be able to modify official check-in or check-out timestamps.
- REQ-ATT-005: The system shall calculate total_work_minutes on check-out.
- REQ-ATT-006: Attendance records shall store IP address, user agent and device info.
- REQ-ATT-007: Employees shall be able to view their own attendance history.
- REQ-ATT-008: Managers shall be able to view attendance for their team.
- REQ-ATT-009: Admins shall be able to view and override attendance (override creates audit log).
- REQ-ATT-010: If check-out is missing at end of day, the system shall create a MISSING_CHECKOUT exception.

### 3.7 Timesheet — MUST HAVE V1

- REQ-TS-001: Employees shall be able to create timesheet entries linked to a project and task.
- REQ-TS-002: Timesheet hours are separate from attendance duration; they shall not auto-match.
- REQ-TS-003: Timesheet statuses: DRAFT, SUBMITTED, APPROVED, REJECTED.
- REQ-TS-004: Employees shall submit timesheets for manager/team lead approval.
- REQ-TS-005: Managers/Team Leads shall be able to approve or reject submitted timesheets.
- REQ-TS-006: Approved timesheets shall not be editable by employees.
- REQ-TS-007: The system shall track discrepancy between attendance duration and timesheet hours.
- REQ-TS-008: Discrepancies shall be classified: NORMAL, MINOR_DISCREPANCY, NEEDS_REVIEW.
- REQ-TS-009: Missing timesheet for a worked day shall create a MISSING_TIMESHEET exception.

### 3.8 Projects — MUST HAVE V1

- REQ-PRJ-001: Admins and Managers shall be able to create and manage projects.
- REQ-PRJ-002: Projects shall have a code, name, description, client, start date, end date and status.
- REQ-PRJ-003: Project statuses: ACTIVE, COMPLETED, ON_HOLD, ARCHIVED.
- REQ-PRJ-004: Employees shall only see projects they are assigned to or have timesheets on.

### 3.9 Tasks — MUST HAVE V1

- REQ-TASK-001: Managers and Team Leads shall be able to create, assign and manage tasks.
- REQ-TASK-002: Tasks shall have priority (LOW, MEDIUM, HIGH, CRITICAL), estimated hours, due date.
- REQ-TASK-003: Task statuses: TODO, IN_PROGRESS, BLOCKED, COMPLETED, CANCELLED.
- REQ-TASK-004: Employees shall be able to update task progress, add work updates and report blockers.
- REQ-TASK-005: Each progress update shall record percentage, time spent, remaining work and blocker.
- REQ-TASK-006: Employees shall be able to mark tasks as completed.

### 3.10 Leave Management — MUST HAVE V1

- REQ-LV-001: The system shall support multiple leave types (Annual, Sick, Casual, Unpaid, etc.).
- REQ-LV-002: Employees shall be able to apply for leave with type, date range, reason and optional attachment.
- REQ-LV-003: Leave request statuses: PENDING, APPROVED, REJECTED, CANCELLED.
- REQ-LV-004: Managers shall be able to approve or reject leave requests with a comment.
- REQ-LV-005: Team Leads shall be able to approve leave for their direct reports (configurable).
- REQ-LV-006: Approved leave must be excluded from absence calculations.
- REQ-LV-007: The system shall track leave balances per employee per leave type per year.
- REQ-LV-008: Applying for leave shall not deduct balance until approved.
- REQ-LV-009: Rejecting or cancelling leave shall restore the balance.

### 3.11 Inactivity Detection — MUST HAVE V1

- REQ-IDLE-001: The system shall detect when no activity signal is received for a configurable idle threshold (default: 30 minutes).
- REQ-IDLE-002: When idle threshold is exceeded during an active attendance session, the system shall create a LONG_IDLE exception.
- REQ-IDLE-003: Inactivity alone shall not automatically mark an employee absent or report misconduct.
- REQ-IDLE-004: The system shall record activity resume events.
- REQ-IDLE-005: The idle threshold shall be configurable in system settings.

### 3.12 Engagement Prompts — MUST HAVE V1

- REQ-ENG-001: The system shall issue configurable engagement prompts during active attendance sessions (default: every 24 minutes).
- REQ-ENG-002: Prompt responses: "I'm Working", "On Break", "Away".
- REQ-ENG-003: The system shall store prompt time, response time, response and response duration.
- REQ-ENG-004: Missing or late responses shall create a note, not automatic punishment.
- REQ-ENG-005: The engagement interval shall be configurable in system settings.

### 3.13 Notifications — MUST HAVE V1

- REQ-NOT-001: The system shall notify employees of check-in/check-out reminders.
- REQ-NOT-002: The system shall notify employees of timesheet submission reminders.
- REQ-NOT-003: The system shall notify employees of leave status changes.
- REQ-NOT-004: The system shall notify employees of task assignments and due date reminders.
- REQ-NOT-005: The system shall notify employees of attendance exceptions affecting them.
- REQ-NOT-006: The system shall notify managers of new leave requests.
- REQ-NOT-007: The system shall notify managers of submitted timesheets awaiting approval.
- REQ-NOT-008: The system shall notify managers of attendance exceptions in their team.
- REQ-NOT-009: Notifications shall support in-app delivery in V1.
- REQ-NOT-010: Email notifications are FUTURE scope.

### 3.14 Attendance Exceptions — MUST HAVE V1

- REQ-EXC-001: The system shall automatically detect and create the following exceptions:
  - LATE_CHECKIN: Check-in after configured standard_start_time + grace_period_minutes
  - EARLY_CHECKOUT: Check-out before configured standard_end_time - grace_period_minutes
  - MISSING_CHECKOUT: No check-out recorded by end of day
  - MISSING_CHECKIN: No check-in on a working day (not approved leave)
  - LONG_IDLE: Idle duration exceeds idle_threshold_minutes
  - MISSING_SELFIE: Check-in or check-out without successful verification
  - TIMESHEET_MISMATCH: Timesheet hours deviate significantly from attendance duration
  - MISSING_TIMESHEET: No timesheet submitted for a worked day
- REQ-EXC-002: Exception severities: LOW, MEDIUM, HIGH.
- REQ-EXC-003: Exception statuses: OPEN, UNDER_REVIEW, RESOLVED, DISMISSED.
- REQ-EXC-004: Managers shall be able to review exceptions and add comments.
- REQ-EXC-005: Exception records shall never be deleted (can only be resolved/dismissed).

### 3.15 Dashboards — MUST HAVE V1

#### Employee Dashboard
- REQ-DASH-EMP-001: Show today's work mode, check-in time, current duration, verification status.
- REQ-DASH-EMP-002: Show today's timesheet summary.
- REQ-DASH-EMP-003: Show assigned tasks with progress.
- REQ-DASH-EMP-004: Show leave balance summary.
- REQ-DASH-EMP-005: Show recent notifications.
- REQ-DASH-EMP-006: Provide quick action buttons: Start Work, Add Timesheet, Update Task, Check Out.

#### Manager Dashboard
- REQ-DASH-MGR-001: Show summary cards: Total Employees, Present, Absent, WFH, Office, On Leave, Late, Pending Review.
- REQ-DASH-MGR-002: Show team attendance table with filters.
- REQ-DASH-MGR-003: Show pending leave requests.
- REQ-DASH-MGR-004: Show open attendance exceptions.
- REQ-DASH-MGR-005: All data scoped to manager's assigned team.

#### Team Lead Dashboard
- REQ-DASH-TL-001: Show attendance for assigned team members only.
- REQ-DASH-TL-002: Show task progress for assigned tasks.
- REQ-DASH-TL-003: Show pending timesheets for approval.
- REQ-DASH-TL-004: Show exceptions for assigned team members.

#### Admin Dashboard
- REQ-DASH-ADM-001: Show global summary cards.
- REQ-DASH-ADM-002: Show charts: daily attendance trend, WFH vs Office, leave trend, timesheet hours, overtime, task completion, exceptions.
- REQ-DASH-ADM-003: Support date range filters: Today, This Week, This Month, Custom Range.
- REQ-DASH-ADM-004: All charts use real database queries, no hardcoded values.

### 3.16 Reports — MUST HAVE V1

- REQ-RPT-001: Daily Attendance Report: Employee, Date, Work Mode, Check-In, Check-Out, Duration, Verification, Status.
- REQ-RPT-002: Weekly Timesheet Report: Employee, Project, Task, Date, Hours, Overtime, Status.
- REQ-RPT-003: Monthly Employee Summary: Working Days, Present, Absent, WFH, Office, Leave, Total Hours, Overtime, Late, Early Checkouts.
- REQ-RPT-004: Team Performance Report: Employee, Attendance Rate, Timesheet Completion, Task Completion, Exceptions.
- REQ-RPT-005: Leave Report: Employee, Leave Type, Dates, Status, Balance.
- REQ-RPT-006: Attendance Exception Report: Employee, Exception Type, Severity, Date, Status.
- REQ-RPT-007: All reports shall support export to CSV.
- REQ-RPT-008: All reports shall support export to Excel (XLSX).
- REQ-RPT-009: Report access shall respect RBAC (employees see own, managers see team, admin sees all).

### 3.17 KPI Calculations — MUST HAVE V1

- REQ-KPI-001: Attendance Rate = (Present Working Days / Expected Working Days) × 100
- REQ-KPI-002: On-Time Check-In Rate = (On-Time Check-Ins / Total Check-Ins) × 100
- REQ-KPI-003: WFH Rate = (WFH Days / Total Present Days) × 100
- REQ-KPI-004: Timesheet Completion = (Submitted Timesheets / Expected Timesheets) × 100
- REQ-KPI-005: Task Completion Rate = (Completed Tasks / Assigned Tasks) × 100
- REQ-KPI-006: Verification Completion = (Successful Verifications / Expected Verifications) × 100
- REQ-KPI-007: Exception Rate = (Attendance Exceptions / Attendance Records) × 100
- REQ-KPI-008: Overtime = max(0, Actual Hours - Standard Hours per day)
- REQ-KPI-009: All KPIs shall be calculated from real data; no hardcoded or fake values.
- REQ-KPI-010: No AI productivity scoring in V1.

### 3.18 Audit Logging — MUST HAVE V1

- REQ-AUD-001: The following actions shall be recorded: LOGIN, LOGOUT, CHECK_IN, CHECK_OUT, TIMESHEET_CREATED, TIMESHEET_UPDATED, TIMESHEET_DELETED, TIMESHEET_APPROVED, TIMESHEET_REJECTED, LEAVE_CREATED, LEAVE_APPROVED, LEAVE_REJECTED, ATTENDANCE_UPDATED, USER_CREATED, USER_UPDATED, USER_DEACTIVATED, SETTINGS_CHANGED.
- REQ-AUD-002: Each audit log entry shall record: user_id, action, entity_type, entity_id, old_value, new_value, ip_address, user_agent, timestamp.
- REQ-AUD-003: Audit logs shall be immutable; no user shall be able to modify or delete them.
- REQ-AUD-004: Only Admins shall be able to view audit logs.

### 3.19 Security — MUST HAVE V1

- REQ-SEC-001: All API endpoints (except login, health) shall require a valid JWT.
- REQ-SEC-002: Passwords shall be hashed using bcrypt, never stored or returned in plaintext.
- REQ-SEC-003: RBAC shall be enforced on every protected endpoint.
- REQ-SEC-004: Rate limiting shall be applied globally and on the login endpoint.
- REQ-SEC-005: HTTP security headers (Helmet) shall be applied.
- REQ-SEC-006: CORS shall be configured to allow only trusted origins.
- REQ-SEC-007: Input validation shall be applied on all request bodies using a schema validator.
- REQ-SEC-008: SQL injection shall be prevented via parameterized queries (ORM).
- REQ-SEC-009: XSS protection shall be applied (sanitization + CSP headers).
- REQ-SEC-010: File uploads shall validate MIME type, file signature, extension and size (max 5 MB).
- REQ-SEC-011: Uploaded filenames shall be generated as UUID-based names, never user-provided.
- REQ-SEC-012: Selfie images shall never be publicly accessible; they require authorization.

### 3.20 Privacy — MUST HAVE V1

- REQ-PRIV-001: A clear privacy notice shall be displayed before webcam activation.
- REQ-PRIV-002: The webcam shall only be active during explicit check-in or check-out.
- REQ-PRIV-003: No continuous recording or hidden webcam access.
- REQ-PRIV-004: Selfie image access is restricted to the employee (own) and Admins/Managers (team).
- REQ-PRIV-005: Selfie retention period shall be configurable (default: 90 days).
- REQ-PRIV-006: Expired selfies shall be deleted from storage and the database reference updated.

### 3.21 Data Retention — MUST HAVE V1

- REQ-RET-001: Selfie files shall be deleted after selfie_retention_days (default: 90).
- REQ-RET-002: Activity logs shall be deleted after activity_retention_days (default: 180).
- REQ-RET-003: Audit logs shall be retained for audit_retention_days (default: 365).
- REQ-RET-004: Data deletion shall: delete storage object, update database reference, create audit record.
- REQ-RET-005: A scheduled background job shall run daily to enforce retention.

### 3.23 Testing — MUST HAVE V1

- REQ-TEST-001: Unit tests shall cover: attendance duration, overtime, late check-in detection, early checkout detection, leave calculation, timesheet calculation, KPI formulas, exception detection.
- REQ-TEST-002: Integration tests shall cover all major API flows.
- REQ-TEST-003: Security tests shall cover: unauthorized API access, role escalation, invalid JWT, file upload validation, SQL injection prevention, rate limiting.
- REQ-TEST-004: Failure tests shall cover: camera permission denied, network failure, duplicate check-in, missing checkout, expired session, invalid image, oversized image.
- REQ-TEST-005: The system shall handle 150+ concurrent users (load test).

## 4. Non-Functional Requirements

- NFR-001: Server timestamps are authoritative. Browser/client timestamps are never trusted for official times.
- NFR-002: Database uses UTC. Display uses configurable timezone (default: Asia/Kolkata).
- NFR-003: Transactions are atomic — partial attendance creation must never occur.
- NFR-004: API responses follow consistent format: { success, message, data } / { success, message, errorCode }.
- NFR-005: The application must be Docker-ready.
- NFR-006: The application must be extensible for future AI verification, payroll integration and microservices.

---

## 5. Out of Scope — V1

- Random camera verification (architecture prepared, disabled by default)
- AI face recognition / liveness detection
- Device verification / OTP
- VPN verification
- Payroll integration
- Email notifications
- Mobile application
- Microservices / Kafka / Kubernetes
- AI productivity scoring

## 6. Use Cases

### UC-001: Employee Login
**Actor:** Employee  
**Flow:** Enter credentials → Validate → Issue JWT → Audit log → Redirect to dashboard

### UC-002: Employee Check-In
**Actor:** Employee  
**Flow:** Select work mode → Click Start Work → Privacy notice → Camera permission → Preview → Capture selfie → Preview/Retake → Confirm → Upload → Backend validates → Server timestamp → Create attendance + verification + audit log → Success

### UC-003: Employee Check-Out
**Actor:** Employee  
**Flow:** Click Check Out → Camera permission → Preview → Capture selfie → Confirm → Upload → Backend validates → Server timestamp → Calculate duration → Update attendance + create verification + audit log → Success

### UC-004: Timesheet Entry
**Actor:** Employee  
**Flow:** Select date + project + task → Enter hours + description → Save as DRAFT → Submit for approval

### UC-005: Task Progress Update
**Actor:** Employee  
**Flow:** Open task → Enter progress % + work update + time spent + blocker → Save

### UC-006: Leave Request
**Actor:** Employee  
**Flow:** Select leave type + dates + reason + optional attachment → Submit → Notification to manager

### UC-007: Leave Approval
**Actor:** Manager  
**Flow:** View pending requests → Approve/Reject with comment → Notification to employee → Update leave balance

### UC-008: Manager Attendance Review
**Actor:** Manager  
**Flow:** View team attendance table → Filter by date/employee/department → Click employee → View details + selfie

### UC-009: Attendance Exception Review
**Actor:** Manager  
**Flow:** View open exceptions → Click exception → Add review comment → Resolve or Dismiss

### UC-010: Report Generation
**Actor:** Manager/Admin  
**Flow:** Select report type + date range + filters → Generate → View results → Export CSV or Excel

### UC-011: Admin Configuration
**Actor:** Admin  
**Flow:** Navigate to Settings → Modify system settings → Save → Audit log created

### UC-012: Admin Attendance Override
**Actor:** Admin  
**Flow:** Find attendance record → Edit timestamps → Save with reason → Audit log created with old and new values
